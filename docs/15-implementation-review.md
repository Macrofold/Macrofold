# Implementation review and decision log

Reviewed September 5–6, 2026. This document records changes made while turning the design into a running product. The design documents describe intended behavior; test evidence and the launch checklist determine what is actually verified.

## Corrections to the original plan

1. **Connector scope was understated.** OAuth token management alone does not provide maintained app tools. Use Composio for customer app integrations behind a ConnectorProvider, with direct MCP for user endpoints. Preserve our own grants, identities and metering. Vercel Connect is an alternative credential adapter, not a second mandatory broker. Better Auth still authenticates our users; the application vault owns model BYOK and infrastructure secrets. Composio managed OAuth accelerates setup; production branding/custom scopes can require our own OAuth applications and provider review. [Integration guide](https://docs.composio.dev/examples/harness-integration)
2. **Realtime does not require a second command protocol.** Keep replayable SSE for agent output and project activity, with ordinary authorized HTTP mutations. WebSockets become justified for shared editing, voice or a raw remote terminal; none is required for this launch. Vercel's current WebSocket feature is beta and its Next.js integration experimental. [Vercel transport](https://vercel.com/docs/functions/websockets)
3. **A durable workflow does not make tool effects exactly-once.** Persist the run and a dispatch record before starting work; fencing and stable execution identity prevent replay from restarting a prompt. An unknown external outcome remains unknown until reconciled. This is a release invariant, not a best-effort convention.
4. **Native snapshots and portable backups have different secrets boundaries.** A provider snapshots the whole filesystem. Backup exclusions are insufficient. Vendor and platform credentials never enter the VM. A short-lived run capability can appear in native session state; it is encrypted in backups and becomes unusable after its run/deadline/lease expires. Diagnostics must not automatically resume a stopped sandbox.
5. **The plan over-specified infrastructure before measuring it.** Start one Next.js application, PostgreSQL, private object storage and managed execution. Use explicit parameterized SQL migrations with node-postgres rather than adding an ORM and a second schema language for database policies. Domain modules own transactions and authorization; small provider adapters own vendor SDK calls. Local development uses real PostgreSQL and filesystem-backed object storage with deterministic execution. Production uses R2 and Vercel. No paid call is necessary to run the local acceptance suite.
6. **Pricing assumptions are not verified margins.** Connector tool execution, backups, minimum runtime billing and failed provider attempts need separate counters. Preserve integer accounting and reservations. Never silently use platform inference funds after BYOK fails. Live paid compatibility is an explicit operator step and cannot be inferred from fixture tests.
7. **Scope visibility is part of the product.** A model/harness route remains unavailable until configured and reviewed. Simulation is visibly labeled. Missing credentials produce actionable setup states rather than fake successful runs. Production readiness fails closed when required infrastructure or safe execution settings are absent.
8. **Revocation requires current authorization state.** Customer and operator OAuth access tokens are opaque. The API calls Better Auth's official introspection action in-process, then validates issuer, audience, current client/resource permissions and membership. This adds database work but avoids a second network hop and makes persisted token revocation effective immediately. Refresh-token revocation invalidates its associated access tokens; previously rotated tokens retain the provider's normal lifetime unless explicitly revoked. Account/session/client revocation is checked separately. Accepted runs delegate through their own deadlines and recheck account, API-key or OAuth-record authority before model/tool calls. Routine access-token expiry does not terminate an accepted two-hour run. Keep expired OAuth records while active runs reference them. [Better Auth OAuth provider](https://better-auth.com/docs/plugins/oauth-provider)
9. **Operation IDs are not bearer permissions.** Store each asynchronous operation's project and required read scope, including exports and file transfers. Polling an operation checks both. Legacy unbound operations fail closed; repeat the original request to obtain a newly bound operation.
10. **Terminal transport and rendering are separate.** A typed command registry uses oclif flag validation; Ink owns the interactive view, and SDK helpers own SSE/cursor recovery. CLI input never executes an agent-suggested local shell command. Git review checkout imports a verified bundle and materializes blobs without checkout filters, so remote attributes cannot trigger locally configured filter programs. Plain terminals use sequential readline chat; Ink permits queued follow-ups while a run streams.

## Code architecture

`apps/web` owns Next.js rendering and transport handlers. `packages/core` owns identity policy, resource operations, execution lifecycle, files, ledger, events, reporting and API dispatch. `packages/db` owns SQL migrations and transaction context. `packages/providers` owns isolated compute, connectors, model protocols, storage, GitHub and payment integrations. `packages/cli` and `sdk` consume the public API; they never connect to the database. `tests` verifies contracts, tenant isolation, real local persistence, browser journeys and terminal behavior.

Keep the visual design compact and calm: a dark navigation rail, bright content surfaces, strong typography, restrained blue accent, inspectable status, and a useful run composer. Use Radix primitives and established editor/table libraries. Product context and current branch remain visible; empty and failure states have concrete next actions. Borrow interaction patterns, not branding or assets, from Linear, Vercel and Stripe.

## Deployment and evidence

The production target remains Vercel, Neon/PostgreSQL, R2, Composio, GitHub App, Stripe and Resend. Provider credentials, DNS, provider consent/review and paid execution smoke are operator-owned launch inputs. See [the step-by-step launch guide](18-launch-guide.md) and [implementation evidence](16-implementation-status.md). A local successful simulation proves the application journey and recovery protocol, not live model or sandbox interoperability.

## 11. Git is a real persistence feature

Workspace creation, editor saves, transfers and completed native runs now produce ordinary Git revisions. Checkpoints retain the Git object graph and refs alongside the full filesystem; ignored files still persist. Workspaces have independent copies of the repository state, so selecting a workspace never shares a writable directory with another run. The CLI exports a standard Git bundle with ancestry, verifies it with native Git, and materializes verified blobs without running local checkout filters.

The control plane uses the established [isomorphic-git](https://github.com/isomorphic-git/isomorphic-git) library, pinned in the lockfile. A system Git binary is not guaranteed in Vercel Functions. Native harnesses continue to use standard Git inside Linux sandboxes. The provider boundary allows a future maintenance-sandbox implementation without changing project/workspace APIs. Current maintenance limits are 250 MiB of tracked files, 250 MiB of Git metadata, and 100,000 entries/objects. Exports additionally bound uncompressed reachable objects. These are explicit MVP limits, not claims of arbitrary repository scale. Larger ignored datasets can remain in the independently persisted filesystem. A Git error produces an attention state while verified file checkpoints remain recoverable.

Control-plane Git reads are confined to a fresh temporary directory. It imports inert objects, refs and index data; it regenerates configuration and excludes hooks, external object alternates and metadata symlinks. Remote URLs come from the verified GitHub repository identity. Transport is restricted to that repository's three smart-HTTP endpoints, disallows redirects, and bounds request/response bodies. Installation credentials stay in memory and never enter `.git/config` or the agent sandbox.

GitHub connection uses user OAuth plus repository write-permission checks, then repository-scoped installation tokens for maintenance. An installation ID in a callback is not proof of authorization; GitHub explicitly [documents the spoofing risk](https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app/about-the-setup-url). Temporary user OAuth authorization expires within eight hours and is used only for connecting/selecting repositories; ongoing project synchronization uses the authorized installation.

Fetch/merge/push preserves native ancestry. Conflicts retain the local files and fetched remote refs for resolution in a native session. Pushes never force-update a remote branch; branch protection and concurrent remote updates can block synchronization without invalidating execution or persistence. Draft pull requests are a separate explicit synchronization mode. Submodule Gitlinks are retained, while recursive submodule fetching and Git LFS hydration are not implicit operations. Those require explicit native-agent handling and appropriate connectivity.

Free verification uses a throwaway bare repository served by actual `git http-backend`, exercising import, push, retry reconciliation, and conflicting local/remote commits. It does not imply a live GitHub account integration was exercised.

## 12. Terminal testing must consume terminal output

The Ink terminal is exercised in a real POSIX pseudo-terminal, including submission, queued follow-up, persistent result, status and detach. The test must continuously drain terminal output while waiting for raw-input initialization and process exit. Otherwise a synchronous terminal write can block the application before its input effect runs, producing a misleading input failure. Noninteractive subprocess, package-install and SSE tests remain separate checks.

Automatic Git publication is an explicit project setting. After a run reaches its persistence commit, the same database transaction queues a separate Git operation. Run results expose pending/synced/blocked/conflict status independently from execution and file verification. Revoked initiating credentials and disabled project policies prevent the queued publication. A local end-to-end test covers the API run, worker, checkpoint, queued Git job, actual smart-HTTP push and final sync result. Incoming GitHub webhooks and optional idle fetch/merge were subsequently implemented; decision 17 records their authorization and ordering behavior.

Portable archives now contain `workspace/` and a separate root `manifest.json`; customer files cannot collide with export metadata. Relative, confined symlinks are preserved without traversal. Object downloads stream verified chunks rather than accumulating an entire large filesystem object in a function's memory. CLI downloads apply a streaming size limit before buffering and replacing local files.

## 13. Queue fairness and delivery semantics

Crash fixtures exposed a scheduler defect: stale entries could fill the first page forever. Admission now marks terminal entries done, preserves active execution identity, and rotates temporarily blocked work. Git jobs use nonblocking advisory acquisition and defer busy workspaces. A maintenance failure does not terminate the local run worker.

Outgoing notifications use a PostgreSQL outbox committed with the terminal run event or Git state. Payloads contain resource references; authenticated API retrieval supplies private results. Delivery has a 10-second deadline, public-HTTPS/DNS-pinned destination checks, eight attempts with jitter, and a stable business event ID. A replay creates a separate delivery record. Secret rotation signs with both secrets for a 24-hour overlap. The receiver verifies `v1,<hex HMAC-SHA256>` over `timestamp + '.' + raw_body`, checks a five-minute window, checks the header event ID against the signed body ID, and deduplicates that ID. Local simulation records deliveries but does not contact configured external endpoints.

## 14. Connector identity and revocation

Direct remote MCP uses the [official TypeScript SDK OAuth client](https://ts.sdk.modelcontextprotocol.io/client): discovery, dynamic registration or operator-preconfigured clients, PKCE, and refresh. A short-lived encrypted state binds the browser, current user, organization, connection and one-time database attempt. The callback consumes the attempt before exchanging its code. Refresh tokens are encrypted and refreshed under a per-connection lock; a tool failure after rotation still preserves the replacement credential. Service identity and authentication method cannot be edited in place, avoiding credential forwarding to a replacement URL. The issuer/token endpoint remains pinned while credentials exist. Creating a new connection is the explicit way to change identity.

Composio remains optional. The operator must enable its [callback identity verification](https://docs.composio.dev/reference/api-reference/connected-accounts) and configure `/integrations/composio/callback` as the verifier. The application redeems the opaque `session_uri` at Composio's fixed API endpoint with the signed-in owner identity, then matches the returned account and toolkit to the pending connection. A link alone does not establish a healthy connection. Organization sharing uses platform grants; upstream execution retains the original connected-account owner identity. This avoids depending on Composio's experimental shared-ACL API.

Disconnect immediately removes platform access and empties grants. A durable cleanup job deletes the Composio account or attempts MCP token revocation when advertised. Unsupported upstream revocation remains a manual provider action; API keys must also be revoked at their provider when that is intended. Cleanup retries without restoring local access, and eventually removes retained platform credentials even if the provider remains unavailable. The grant intersection, current actor, lease, deadline and cancellation state are rechecked at committed tool admission.

## 15. Credits, reversals and payment ordering

The commercial model remains prepaid PAYG and monthly Pro. Credit lots make purchased and expiring subscription funds distinct. Earliest-expiring credit is consumed first. Existing reservations protect their share until settlement; only the unused released share expires. Cash reversals append new journals and can create debt after consumption. New funding pays that debt before becoming spendable. API balance displays clamp spendable credit at zero and separately report debt. SQL permissions prevent the runtime role from updating or deleting historical journals and financial deduplication records.

Checkout orders bind organization, Stripe customer, expected amount and session ID. Signed completion events cannot grant arbitrary metadata amounts. Subscription state is retrieved while processing under the organization lock, avoiding stale entitlement restoration from out-of-order notifications. Paid recurring invoice lines grant one included-credit journal and bind its funding payment intents. Refunds and disputes share a capped reversal calculation; previously expired unused credit is not debited again. Open disputes block new work and request cancellation. Successful dispute reversals become nonexpiring correction credits, a deliberate customer-favorable policy that avoids reinstating already-expired credit after a long dispute. Subscription renewal credits still expire normally.

Stripe verification uses signed local webhook fixtures and injected provider responses. No test charge, real payment, model request or cloud sandbox was created. The [subscription webhook guide](https://docs.stripe.com/billing/subscriptions/webhooks) and pinned SDK types define the invoice/subscription event handling. Full payment reconciliation, storage metering, live configuration and launch verification remain separate work items.

## 16. Account security and controlled tool execution

The implementation adds Better Auth TOTP with recovery codes, device revocation and signed OAuth consent. Account-level application revocation explicitly revokes both access and refresh tokens; removing a consent record alone is not sufficient. These flows are tested through real browser sessions and the actual OAuth provider. Providers may expose reasoning summaries and tool events; the product does not promise access to private model reasoning.

Search is a budgeted broker tool backed by Brave. Managed and BYOK funding remain explicit. Stdio MCP packages run inside the already allocated customer sandbox through the official MCP SDK, with an operator-reviewed executable/argument/tool catalog. They never spawn on the API host. Stdio package credentials are intentionally visible to the customer's own sandbox processes. The default reviewed package is the official filesystem server. Discovery from the catalog is free; the first actual invocation uses the allocated runtime. An invocation marker and the central journal prevent automatic replay after a lost acknowledgement.

Direct R2 staging solves Vercel's request-size limit. Presigned PUTs bind exact object identity, length and type; verified content is application-encrypted before checkpoint publication. Raw staging uses TLS and provider encryption until that point. Expired capabilities are cleaned by maintenance, with a one-day R2 lifecycle fallback. Six-MiB browser transfers and independent SigV4 verification pass locally. Actual native stdio execution passes in a network-disabled Docker sandbox; native harness continuation passes again after the image rebuild.

## 17. Incoming GitHub events are hints, not filesystem replacements

The GitHub webhook validates HMAC-SHA256 over exact bytes before reading a minimal installation-to-organization routing table. A receipt and all tenant work are committed together. Content and grants remain under tenant RLS. Repository removal and installation suspension/deletion revoke local grants; queued jobs verify both installation and exact repository permission before obtaining a token. An added/unsuspended event never silently restores access. Reconnect through current user authorization instead. An already dispatched external operation cannot be recalled by a webhook.

An incoming target-branch push records remote-change metadata. Automatic fetch/merge is a separate opt-in from automatic post-run publication. Notifications coalesce per workspace; busy workspaces are deferred, and the Git worker fetches current remote state rather than trusting an event's hash or arrival order. Conflicting local content is preserved. Explicit fetch/merge remains available. The ingress is bounded to 4 MiB to fit the hosting envelope; unusually large or undelivered GitHub payloads require a subsequent fetch. GitHub itself caps events at 25 MB. [GitHub payload and delivery headers](https://docs.github.com/en/webhooks/webhook-events-and-payloads), [signature validation](https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries).

## 18. Team authorization belongs to the organization domain

Better Auth owns the human identity and browser/OAuth sessions. The domain owns organization memberships because the same roles are enforced by the API, model gateway, tool broker, Git jobs, and billing. Organizations are explicit credential selectors; an API key remains bound to one organization. Browser selection uses an HttpOnly same-site cookie and revalidates membership on every request. Switching reloads the dashboard so cached resources from the previous organization cannot appear in the new one. OAuth clients can discover memberships through `/v1/me`, but must select an organization for other multi-membership requests.

Owners can grant ownership; admins can manage members/viewers. Membership mutations serialize under an organization lock and retain at least one owner. Invitations last seven days, bind the recipient's verified email, require the inviter's current authority, and are single-use. Links are shared explicitly rather than sending unsolicited email. Removing a member or changing them to viewer revokes their API keys and requests cancellation of their work. Subsequent model/tool calls recheck current authority. Role changes and invitation events appear in a tenant access audit. Browser journeys, cross-tenant invitation tests, and simultaneous-owner-demotion tests pass.

## 19. Reconciliation and key rotation are operational features

Hourly organization maintenance expires unreserved credit and compares independent credit-lot, ledger, debt and run-reservation facts. A mismatch sets a spending hold and records evidence. It never writes an invented financial correction. The operator reporting API/MCP exposes reconciliation and queue-health metrics with evidence-linked recommendations; infrastructure changes remain reviewed operator actions. Financial reads compute the effect of pending expiration without mutating the ledger. Five organizations are claimed per maintenance sweep using SKIP LOCKED; claims rotate and recover after failure. Higher scale requires more dispatch sweeps and database/provider capacity measurements.

Versioned AES-GCM envelopes carry an authenticated key identifier. New writes use the active key; retained keys decrypt old objects and credentials. `scripts/rewrap-vault.ts` provides a dry run and a paused-writer re-encryption pass. It scans encrypted content and the platform's encrypted database fields without printing values. Keep legacy keys for outstanding capabilities/invitations, backups, and any values not yet rewrapped. Key retirement is an operator recovery decision, not an automatic cleanup. No migration changes or rewrites historical financial journals.

## 20. Storage retention is independent of execution success

Physical object inventory is paged through the ObjectStore port. Tenant transactions take a shared storage lock; destructive maintenance takes an exclusive lock and checks for active/queued runs before pruning or collection. Native work outside a short database transaction remains protected by its active run record. A completed inventory traverses retained file, Git, session, artifact and execution references, including encrypted chunk-manifest children. Missing/incomplete reference graphs defer collection. Unreferenced objects must remain unreferenced and old for fourteen days before deletion, in bounded batches. A failed sweep can safely retry; it cannot publish a new reference while collection holds the exclusive lock.

Checkpoint retention keeps all revisions for 24 hours, one daily for 30 days, one weekly for 12 weeks, pins, current/base checkpoints and checkpoints referenced by runs still in the detailed-history window. Retained immutable objects are deduplicated per organization. Temporary raw staging and provider snapshot caches are outside the customer storage meter. The 14-day object delay supports recovery from appropriately recent database backups; it is not a promise that all historical database snapshots can be restored after their referenced objects expire.

Storage overage is **off by default**. Billing exposes measured bytes, observation time, allowance, explicit enablement and a UTC-month spending ceiling. Additional physical storage costs $0.10/GiB per fixed 30-day month, prorated using the previous completed observation and integer fractional carry. A meter outage never back-bills more than two hours of unobserved time. Credit reservations and the customer's storage budget bound actual debits; the platform absorbs excess liability. Quota exhaustion blocks new runs/uploads/editor writes while retaining downloads and recovery. Already accepted runs/transfers can exceed the measured allowance while persisting; preservation takes precedence, and subsequent work stops when measured. This intentionally accepts bounded operational overshoot instead of discarding a completed run's files. New checkpoint publication requests an early scan.

Tests cover manifest reachability, pins/current revisions, old checkpoint expiration, delayed collection, serialization against a concurrent tenant writer, physical-byte metering, fractional charges, capped prepaid debits, and independent ledger reconciliation. These use PostgreSQL and a deterministic object-store fixture without paid storage calls.

## 21. Deletion preserves the audit without keeping result content forever

Archiving remains reversible and retains files. A separate `projects:delete` scope schedules permanent deletion, restricted to owners/admins. The dashboard requires the exact project name and recent authentication, supports a password challenge for older sessions, and provides an archived/pending view with undo. Scheduling requests cancellation and pauses new runs. Maintenance waits for the seven-day window and an idle tenant before clearing project files, native session state, artifacts, execution copies and detailed outputs. It retains accounting/usage identities. Encrypted idempotency responses become 410 tombstones so old mutations cannot be replayed to restore deleted content.

Detailed run history has a separate 30/90-day PAYG/Pro lifetime. Expiration removes prompts, instructions, tool payloads and output deltas, while retaining terminal event sequence/identity so historical SSE replays still finish correctly. The UI explains expired content instead of waiting for an output that no longer exists. Local database tests exercise expiry, terminal replay, deletion scheduling/undo, content removal and later physical collection; a browser journey verifies the confirmation, archived view and undo with an accessibility audit.

## 22. Pagination and metrics must remain true as data grows

Customer collections use explicit cursor pagination in both REST and dashboard controls. Project/file search runs on the server before pagination; browser filtering over a truncated first page is insufficient. File cursors use the same code-point order as sorting, avoiding locale-dependent skips. Dashboard aggregate cards use SQL counts rather than the number of rows fetched for a preview. Organization-wide request and financial reports reject project-restricted credentials. Request observations begin before handler execution, attach identity after authentication, and finish with status/latency; interrupted observations remain identifiable by missing status. Logs contain request IDs and error codes, not bodies or credentials.

Growth definition version 2 separates verified humans, successful human mutations, successful service-key traffic and organization activation. Activation requires a successful non-simulator run. Weekly account cohorts calculate seven-day activation and second-week return usage with complete observation denominators. Operator-marked internal organizations are excluded from growth; usage/financial reporting retains all recorded facts. Human acquisition currently uses current organization membership, so historical human counts can change when membership is removed. Stored daily UTC reports preserve the observation and expose missing sources; live reports can include later records. Reports use established PostgreSQL aggregates instead of sending customer data to an analytics vendor by default. The optional PostHog adapter consumes the metadata-only event table, as described in decision 25.

## 23. Portability uses the existing durable domain state

The accepted production scheduler remains Vercel Workflow. A conventional SQL poller is the tested replacement target for a standalone Node host. Both call the same `advanceCloudRun` state machine and resolve the same machine-provider factory. The prior PostgreSQL Workflow World plan is revised: the initial portable path does not need a second persistence system for Workflow history because accepted runs, bounded phases and retries already live in the domain database. This costs a small scheduler implementation but reduces deployment pieces and makes its crash behavior explicit. The cloud provider remains Vercel; portability is not a claim of interchangeable native memory snapshots or automatic credential migration. See [deployment packaging](22-deployment.md).

## 24. Recovery is verified at the application boundary

The fresh-install rehearsal now takes a real PostgreSQL custom-format dump, restores into a second disposable database and copies the encrypted object store independently. It retains the rotated vault keyring, then reads files by hash through the restored application, authenticates the restored scoped key, continues a prior session and replays its terminal SSE event. This verifies more than the existence of a backup file. Production PITR/object policy and external credentials still require their own operator rehearsal; provider-native recovery snapshots are not independent backups.

## 25. Optional analytics does not sit in the request path

The native product-event table is authoritative for metadata observations. Optional PostHog batch export is disabled by default, requires an explicit starting timestamp and daily attempt budget, and forwards an allowlisted projection with stable event identity. Native reporting continues if delivery is unavailable. The boundary uses PostHog's documented batch API because the application already owns a durable SQL outbox; a second in-memory retry queue would add no durability. No raw event metadata, prompts, tokens, files, names or emails are forwarded. Tenant exclusion and personless pseudonymous attribution are explicit. Operators own vendor pricing/consent/retention configuration.

## 26. Release critique: choose measured guarantees over an oversized launch surface

The original plan mixed implemented requirements with aspirational conveniences: restic maintenance VMs, a browser desktop, live provider invoice/quota readers, many operator BI pages, one-click account closure and universal provider migration. The current documents replace those claims with the actual bounded product. Persistent projects, three native harnesses, explicit MCP grants, Git, API/CLI/dashboard, prepaid billing and native operating reports remain the core. Browser automation, enterprise identity and additional sandbox providers require independent extensions. Account closure and provider accounting are explicit operator procedures rather than silent incomplete APIs.

A global run ceiling now complements tenant limits; all schedulers serialize its reservation. Thirty-two simultaneous funding claims cannot exceed the same balance, and request bursts remain isolated by credential. The tests are concurrency evidence, not a production throughput benchmark. Raw request/activity metadata has bounded 400-day retention and old report queries disclose missing sources. Operator access audits are immutable. A longer retention requirement must be an intentional policy/migration.

CLI release testing found an interaction between soft deletion and operation authorization: a workspace deletion tried to resolve its own already-hidden workspace while creating its operation. The operation now carries the previously authorized project binding. Deletion additionally rejects queued work as well as an active writer, preserving cancellation and budget semantics. Cross-platform materialization rejects reserved names, metadata aliases, symlink ancestors and case-insensitive collisions before creating a local worktree.

The dependency audit found vulnerable transitive `nanoid` and `undici` versions under Workflow. Narrow compatible overrides select 5.1.16 and 7.29.0 respectively; the subsequent production dependency audit returned zero known findings. This is a point-in-time package audit, not a full security certification. [Nanoid advisory](https://github.com/advisories/GHSA-28wg-ghj8-5hjv), [Undici advisory](https://github.com/advisories/GHSA-4cwx-7wf7-3272).

## 27. Release artifacts and UI must follow the same public contracts

The final onboarding review found obsolete terminal commands and a missing composer binding for configured tools. The project header now copies actual login/link commands, run creation selects explicit previously approved tools, and saved presets can be selected without silently overriding their harness/funding/grants. Browser acceptance checks the emitted public request and completed simulation. Merely creating a connector did not previously make it usable from the composer.

Native image packaging now uses pnpm's dedicated deployment lockfile instead of legacy deployment of the shared workspace graph. This removes unrelated web/control-plane dependencies from the runtime image while retaining pinned harness packages. The built runtime shrank from about 1.75 GB to 1.12 GB. Native acceptance uses the actual image contents without overlaying freshly compiled source. [pnpm deployment behavior](https://pnpm.io/cli/deploy).

## 28. Production packaging must exercise the local profile deliberately

The standalone production server enabled Better Auth's default login throttling despite the unpaid local profile, causing rapid browser fixtures to share one IP allowance. Authentication throttling is now explicitly disabled only for `PLATFORM_MODE=local`; production uses PostgreSQL-backed counters shared across Functions and retains the provider's sensitive-endpoint rules. A two-instance integration test checks shared denial. Authentication migration creates the counter table/index; maintenance removes counters older than one day in bounded batches. Public deployments must overwrite forwarded-IP headers at a trusted edge and keep direct origin access private. [Better Auth rate-limit storage and proxy guidance](https://better-auth.com/docs/concepts/rate-limit).

The new multi-action project header also exposed a 390-pixel overflow. Header actions now wrap below the title on mobile; the same full browser journey is rerun against the updated container.

## 29. Protect unsaved editor state and align fixture configuration

Background file-query refreshes must not replace a dirty editor buffer or advance its observed revision. The editor now preserves the draft, rejects a stale save, disables workspace/run context changes until save/discard, and confirms normal navigation/unload. Discard explicitly reloads checkpoint-backed content. Editing is disabled while a save is in flight. A browser regression changes the remote file underneath a local draft and verifies preservation, stale-write rejection and explicit recovery.

The browser runner now loads the same guarded local configuration as the app/worker. Previously, direct fixture SQL fell back to the original database after the preview moved to a new database, so test verification updates affected no user and sign-in correctly returned Email not verified. Loading the shared configuration fixes the test harness; no production verification bypass was added.

## 30. Review protocols and interfaces together

The [September 6 code review](23-code-review.md) records file-tree validation, pre-execution cancellation, hosted-tool budget isolation, independent OAuth refresh transactions, SDK error compatibility, paginated discovery with concurrent grant protection, drained subprocess output and shared idempotency/SSE recovery. Shared Radix selects replace native dashboard menus; Recharts consumes authoritative daily usage aggregates. The review retains the modular monolith and makes the actual vendor boundaries explicit. ## 31. Durable waiting and weighted account scheduling

[Scheduler design](25-scheduling.md) implements three plans, customer execution caps, 24-hour new-job deadlines, and PostgreSQL-coordinated weighted turns under the existing global capacity lock. Interactive requests have first consideration without preemption; unused capacity remains available for background work. Bounded aging and workspace FIFO prevent a backlog from being treated as one global queue. The API, CLI and dashboard expose reasons/deadlines/held funds, not guessed queue positions. Waiting Workflows return to the SQL outbox instead of accumulating provider history for 24 hours.

The multi-process load test demonstrated a foreign-key lock-upgrade deadlock between checkpoint inserts and financial settlement. Organization projection locks now use `FOR NO KEY UPDATE`: they still serialize balances but coexist with foreign-key `KEY SHARE` locks. It also demonstrated the local worker's batch-wide wait wasting free slots; a bounded local dispatcher now polls while executions continue. No queue service, custom autoscaler or replacement global lock was added. Live provider quotas, recurring Stripe tier switches and cloud event volume remain operator acceptance gates.
