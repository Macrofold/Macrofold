## Operations that require an explicit test budget

The following gates are **not live-verified**. Provisioning/hosting, storage, model use, search, connector calls and analytics ingestion may incur charges. Set limits in both the platform and each vendor account, agree on a small test budget, and perform these deliberately. A provider's free tier is not a guarantee that the operator's current account has unused allowance.

### Vercel Sandbox, VCR and Workflow

1. Build the native image for Linux AMD64, publish to the intended VCR project, wait for **Ready**, and configure its immutable digest. Verify the SDK workload identity has access to that exact project/team. Image upload/preparation may be billable.
2. Enable paid execution only in the controlled acceptance environment. Submit one minimal project run through `POST /v1/runs` with a small explicit budget and timeout. Verify a previously nonexistent execution name creates exactly one sandbox, with the expected image, two vCPUs and egress policy.
3. Observe Workflow dispatch, lease acquisition, supervisor launch and durable SSE output at `/v1/runs/{id}/stream`. Disconnect/reconnect the stream and verify replay from the event cursor. Test one input-required interaction, cancellation and timeout. Repeat through the CLI and dashboard.
4. Write a test file, finish the run, inspect the checkpoint, then run again and read that exact file plus a native session continuation. Confirm `/v1/runs/{id}/result` and historical events remain readable after execution stops.
5. In the test environment, interrupt one execution and one workflow delivery. Verify no ambiguous prompt or tool side effect is automatically replayed. Partial files must remain either verified in a checkpoint or explicitly recoverable; a failed run must not silently look empty.
6. Verify the original session is fenced: a stopped or replaced session is not resumed by a probe or retried launch. Confirm retained snapshot IDs/expiration, final sandbox stop/delete behavior and no abandoned billable VMs. Run minutely `/internal/maintenance` through the configured scheduler and verify overdue work is reclaimed safely.

The review fixed an SDK mismatch discovered without spending: `@vercel/sandbox` 3.2.1 exposes lookup failure status as `APIError.response.status`. The adapter now recognizes its actual 404 before creating a new sandbox. Regression tests construct the real SDK error, reject 403/429/500 lookup ambiguity, and simulate a lost creation acknowledgement without starting a VM. **This adapter evidence still requires the real-project steps above.** [Vercel Sandbox SDK](https://vercel.com/docs/sandbox/sdk-reference), [Vercel Workflows](https://vercel.com/docs/workflows).

### R2 persistence, staged uploads and recovery

1. Use a separate private test bucket with the production CORS/lifecycle rules. Upload a small file and a file above the direct-upload threshold through the dashboard and CLI. Exercise signed `PutObject`, `GetObject`, `ListObjectsV2` and `DeleteObject` using the actual bucket endpoint through the application.
2. Verify exact-origin browser CORS, signed content length/type, expired URL rejection, hash mismatch rejection and bounded staging completion. Confirm the bucket is private and no bucket credential is present in the sandbox or browser.
3. Read the file after a different run/session and compare SHA-256. Exercise checkpoint restore, Git metadata, native home and portable export/import. Verify ordinary customer files named `manifest.json` do not collide with archive metadata.
4. Inventory objects, test retention in a dedicated disposable organization, and verify referenced checkpoints remain reachable. Do not shorten live customer retention to speed this check. Confirm temporary staging objects expire, while persistent content has no blanket age-deletion policy.
5. Back up SQL, the encrypted object set and recovery keys at a consistent point. Restore into independent SQL/object storage and authenticate, read files, continue a session and inspect historical usage. Record measured recovery time and any missing objects.

R2 supports a subset of S3, so local SigV4 fixtures do not establish deployed bucket policy, CORS, checksums or account permissions. The pinned AWS SDK uses required-only request checksums to preserve R2 compatibility. R2 operations/storage may be billed even for a small probe. [R2 S3 compatibility](https://developers.cloudflare.com/r2/api/s3/api/).

### Model gateway and all native harness routes

For **every enabled harness × provider/model × funding mode**, run this sequence. Do not infer one route's success from another. OpenCode uses the configured OpenAI, Anthropic or OpenRouter protocol, so include each supported mapping that the UI exposes.

1. Submit a minimal run with a text-only response and one allowed local filesystem tool; stream it through the native harness and gateway. OpenAI routes use `POST /v1/responses` or `/v1/chat/completions`; Anthropic uses `/v1/messages` and, when requested by the harness, `/v1/messages/count_tokens`; OpenRouter uses `/api/v1/chat/completions`.
2. Inspect completion, tool events and usage. Compare input/output/cache accounting and the platform credit ledger to the provider's request/usage records. Include a long enough continuation to test cached input where the selected model supports it. Visible reasoning summaries are stored only when a provider exposes them; private internal reasoning is not guaranteed or fabricated.
3. Repeat as customer BYOK, then revoke the BYOK key and repeat a minimal request. It must fail without using the operator key. Confirm BYOK inference is absent from managed model charges while authorized compute/tool costs remain visible.
4. Check an insufficient budget, unsupported endpoint, disabled model and revoked connection. They must fail before funded inference. Confirm platform-hosted server tools, media generation and premium execution features that lack a reviewed rate-aware path are rejected.
5. Test a streaming interruption/unknown-usage case in the controlled environment. The ledger must expose uncertainty and follow reconciliation rules, rather than silently booking zero or resending the prompt. Resolve any circuit breaker only after investigating the actual provider evidence.

The local native-image tests run actual pinned binaries with loopback model fixtures and no external network. They verify adapter/session/tool shapes; they do not prove current paid model availability or account limits. ### GitHub, connectors, MCP, web search and stdio tools

- **GitHub:** Import a dedicated private repo, create a remote worktree, edit a file, fetch/merge a new upstream commit, push a branch and create a draft PR. Test a deliberate merge conflict, ignored-file collision, branch protection denial, webhook duplicate and revoked installation. Expected: files remain intact, Git sync has its own status, push never force-updates, and a retry does not create duplicate PRs. GitHub API operations may be free, but they require actual ownership/credentials and the hosting/storage path may cost money. No private repo was used in live tests. [GitHub REST metadata](https://docs.github.com/en/rest/meta/meta?apiVersion=2022-11-28).
- **Composio:** After identity verification, invoke one explicitly granted read action in a disposable account. Confirm the pinned toolkit version, mapped arguments/result, usage fact and charge. Revoke the tool grant/account and repeat: reject before a new action. Test a later-page tool and failed/cycling discovery. Catalog collection is bounded to 5,000 tools, 8 MiB, 100 pages and one 15-second discovery deadline; excessive/incomplete catalogs fail explicitly, without silently granting a partial list. [Composio v3.1 tools](https://docs.composio.dev/reference/api-reference/tools/getTools).
- **Remote MCP:** With the actual server, invoke one reviewed read-only tool, then test denied, expired and refreshed authorization. Confirm tool-call IDs, content limits, run-specific grants and cancellation are represented correctly. Preserve a failed action as uncertain when it might have executed; do not retry a side effect blindly. Exercise a multi-page catalog because page size belongs to the server. [MCP pagination specification](https://modelcontextprotocol.io/specification/2025-11-25/server/utilities/pagination).
- **Brave Search:** Make one intended query through an explicitly granted `web_search` tool using `GET https://api.search.brave.com/res/v1/web/search`. Verify source title/URL/excerpt, result count, safe-search setting, timeout/quota failure and per-call usage reservation/charge. Repeat BYOK versus managed funding if both are offered. No search request was made here because queries consume usage.
- **Stdio MCP:** For each allowlisted package/version, invoke one reviewed filesystem or test-service tool inside the actual Sandbox image. Confirm selected environment secrets, approved args, process isolation, file persistence and call deduplication. Revoke the grant and prove it no longer executes. The local filesystem stdio fixture passed with networking disabled; cloud image policy and third-party service credentials remain unverified.
