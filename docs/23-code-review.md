# Code and interface review — September 6, 2026

This review examined the application source across the web app, domain/application services, SQL migrations, provider adapters, native runtime, CLI, both SDKs, infrastructure, scripts and tests. It focused on authorization, persistence, spending, concurrency, protocol compatibility, retries and user-visible failures. Generated contracts were checked through their generators rather than hand-edited. The result preserves the existing product scope and Vercel-first deployment.

## Standards and architecture decisions

Keep the modular monolith. SQL transactions and explicit resource ownership are useful boundaries for this product; splitting billing, runs and files into independently deployed services would introduce distributed consistency work without current traffic evidence. `packages/core` contains both policy and application orchestration: some integration services intentionally compose vendor SDKs. It is not a completely vendor-free domain package. Machine execution uses domain-owned ports; HTTP handlers remain thin; public clients never access SQL. Extract additional adapters when there is a concrete alternate implementation or testing need, rather than adding forwarding layers everywhere.

The review used [Next.js data-security guidance](https://nextjs.org/docs/app/guides/data-security), the installed Next.js 16.3.4 documentation, [OWASP API Security](https://owasp.org/www-project-api-security/), and [OWASP SSRF prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html). Applied rules include current authorization at the resource boundary, restricted database roles, transaction-local tenant context, secret-free browser DTOs, bounded payloads, DNS-pinned remote destinations, and no automatic replay of ambiguous side effects. These sources guide the review; this is not a formal security certification.

React state should represent user choices, with compatible model/project values derived from the current catalog. [React's effect guidance](https://react.dev/learn/you-might-not-need-an-effect) informed removal of redundant selection effects. Shared display components now live outside the dashboard router, breaking circular imports. [Next dynamic imports](https://nextjs.org/docs/app/guides/lazy-loading) load the selected dashboard view, editor and chart when needed. The browser consumes the same built SDK streaming package as public customers; web dev/build and clean verification build that workspace dependency first.

TypeScript now enforces unused-local and unused-parameter checks in addition to strict typing. Unused imports, duplicate request-body readers, redundant authorization checks already enforced by current-actor helpers, duplicate terminal checks and a second browser SSE implementation were removed. Removal was limited to responsibilities with an existing authoritative implementation; checks at independent trust boundaries remain.

## Correctness changes

| Finding | Implemented correction | Verification |
|---|---|---|
| A file `a` and child `a/b` could coexist in checkpoint metadata even though the tree cannot be restored normally | Central file-tree validation before publication, transfer application and restore; reject file/symlink ancestor collisions and directory replacement conflicts | Real SQL/files/transfer/restore regressions; rejected changes preserve the prior revision |
| Concurrent workspace creation relied on a SQL uniqueness failure and could race default selection | Serialize project workspace creation; preserve the existing unique branch constraint and return a domain conflict | Concurrent same-branch creation regression; one workspace and deterministic conflict |
| Hosted model tools could create extra services outside the text/tool reservation | Provider-specific allowlist for client-executed tool definitions; reject hosted code interpreter, remote MCP, plugins and service containers before forwarding/reserving | OpenAI/Anthropic/OpenRouter payload tests prove rejection before upstream calls; normal client function/tool forms remain supported |
| Five requests holding domain connections could wait for nested OAuth refresh on the same exhausted pool | Dedicated maximum-two-connection credential pool with the same restricted role/RLS; refresh commits independently; it does not reacquire filesystem maintenance locks | Pool saturation, rollback, tenant isolation and waiting-GC regressions |
| Queued cancellation could reach the simulator before its first heartbeat | Admission checks cancellation and current workspace availability before execution | Queued cancellation/current-state regression |
| Sandbox SDK 404 was stored at `APIError.response.status`, but adapter only checked top-level fields | Normalize the actual installed SDK error shape; create only after confirmed not-found; retain same-name reconciliation after a lost create response | Installed SDK error instances for 404, 403, 429 and 500 plus ambiguous-create fixture; no real sandbox created |
| Remote MCP/Composio tool discovery ignored later pages | Follow provider cursors with bounded catalog/page size, reject ambiguous/duplicate catalogs, close MCP sessions on failure | Multi-page protocol fixtures and failure cleanup |
| A grant update could overwrite a concurrent change while discovery was in progress | Discover before the row lock, then compare the current revision under lock | Concurrent stale grant update regression |
| Process exit could be observed before stdout finished draining | Finalize captured subprocess output on Node's `close` event; reject requests made to an already closed native RPC process | Delayed trailing-output regressions and actual native harness fixtures |
| A failed or truncated mutation response could lose the recovery identity | SDKs retain the idempotency key even after successful headers and a broken body; CLI JSON exposes optional `error.idempotency_key`; dashboard retains bounded opaque recovery hashes/keys for an explicit unchanged retry and only clears the key confirmed by that response | TypeScript/Python transport regressions and a browser test that commits a project, drops its response, then recovers exactly one project |
| Browser stream handling duplicated parsing/retry logic and could keep retrying revoked access | Reuse SDK streaming through a same-origin cookie adapter, remove browser bearer headers, stop permanent failures, expose the problem while retaining status reads | UTF-8/cursor/cancellation protocol tests and denied-stream browser journey |
| Malformed login return URLs and async auth errors could escape UI/server boundaries | Shared validated same-origin return path; await the auth handler inside its error boundary | Malformed URL, cross-origin and asynchronous failure tests |
| Run-page terminal hint named a nonexistent command and shortened the ID | Show `agent run attach` with the complete run ID | Browser assertion against the public CLI contract |

Node's [child-process event contract](https://nodejs.org/api/child_process.html#event-close) distinguishes process termination from drained stdio. MCP's [pagination contract](https://modelcontextprotocol.io/specification/2025-11-25/server/utilities/pagination), [Composio catalog API](https://docs.composio.dev/reference/api-reference/tools/getTools), and [Vercel SDK reference](https://vercel.com/docs/sandbox/sdk-reference) were checked against the installed dependencies. The model restriction follows the documented distinction between [local and hosted shell execution](https://developers.openai.com/api/docs/guides/tools-shell) and [client tool definitions](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-reference).

## Interface decisions

Use the established Radix primitives already present in the app, extended with `@radix-ui/react-select`, and Recharts for charts. Keep Tailwind 4 and the existing shared CSS tokens; adding another component framework or CSS runtime would duplicate responsibilities. New control/chart styles are colocated with their components. Exact versions and transitive dependencies are locked, audited and included in the declared-license inventory.

All dashboard selects now have designed menus, consistent spacing, selected-state checks, typeahead, scrolling, disabled items, visible focus, Escape behavior and focus return. Radix owns keyboard/focus behavior; a small shared wrapper owns product styling and empty-value handling. Visible field labels explicitly reference their controls. Menus portal above dialogs and respect viewport collisions. [Radix Select](https://www.radix-ui.com/primitives/docs/components/select) and the [WAI-ARIA combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) define the expected interaction.

Usage now shows an interactive daily bar chart for runs, input tokens, output tokens and run charges. It consumes the existing server `group_by=day` report, independent of the paginated request table. A seven-day range includes today and six preceding UTC dates. The chart fills dates with no facts, marks missing provider observations unknown, offers a daily-values table, and shows an intentional empty state. Period changes preserve the selected metric and expanded table. Run counts/charges use the run's admission date; token observations use their recorded date, as defined by the reporting API. Charges are usage ledger totals, not Stripe payment receipts. Recharts' [accessibility layer](https://recharts.github.io/en-US/api/BarChart/) supplements the semantic table.

Spacing, typography, tabular numbers, focus treatment and restrained transitions follow [Vercel's interface guidelines](https://vercel.com/design/guidelines). Motion uses CSS opacity/transform and honors reduced-motion preferences; no large animation library is needed for these interactions. Mobile selects have a 44-pixel minimum height, and text inputs avoid iOS auto-zoom without disabling user zoom. Desktop and 390-pixel layouts are tested and visually inspected. Automated axe checks are evidence of specific rules, not a complete accessibility audit.

## Deployment implications and limits

Each process may open **five domain + three identity + two credential connections**. Vercel instances and standalone workers multiply that ceiling. Keep headroom for migrations and operations, use the provider's supported pooling, and measure database pressure before raising concurrency. Credential transactions preserve RLS and are used for OAuth credential changes and expiry-notification metadata, never filesystem-object changes. They use the normal restricted runtime role, not a separate SQL privilege boundary.

The public HTTP contract remains compatible. The CLI's machine-readable error envelope adds one optional recovery-key field. No database migration is needed for this review. Rebuild the application, SDKs, worker and native runtime image from the same revision before release; an old image does not acquire source fixes automatically.

The eight free live provider probes verify public metadata or unauthenticated rejection, not authenticated operation. Every credential-dependent, metered or deployed-environment check is listed with its endpoint and expected outcome in [the pre-deployment checklist](21-pre-deployment-checklist.md). Disabled optional integrations stay disabled until their checks pass. Current test counts and build evidence belong in [the verification record](16-implementation-status.md).
