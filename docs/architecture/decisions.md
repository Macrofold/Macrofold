# Accepted architecture decisions

The [architecture overview](README.md) describes current ownership. This document records the major decisions and their tradeoffs; feature documents own implementation details. [Release status](../status/README.md) and [deployment acceptance](../operations/pre-deployment.md) define what has actually been verified.

## Current decisions

| Decision                                                       | Rationale and boundary                                                                                                                                                                                                                                                                                                                     |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A modular Next.js/TypeScript application                       | One same-origin dashboard/API deployment with domain services outside the framework. Explicit SQL and numbered migrations avoid duplicate ORM/schema policy. Established Radix, TanStack and CodeMirror components own common UI behavior.                                                                                                 |
| Vercel-first with an application-owned execution state machine | Workflow drives bounded domain phases; the standalone PostgreSQL poller uses the same state. Stable execution identity and fencing prevent prompt replay after an ambiguous launch. Portability requires provider engineering and credential/data migration. [Portability](portability.md).                                                |
| Separate durability from delivery                              | PostgreSQL owns accepted runs, events, ledger and jobs. Detailed run SSE is replayable. Dashboard freshness is a private best-effort category stream with periodic API reconciliation. Outgoing webhooks retain their separate durable outbox. [Live refresh](../features/dashboard/live-refresh.md).                                      |
| Native harnesses inside isolated compute                       | Codex, Claude Code and OpenCode use native adapters. The protected supervisor controls files and credentials; arbitrary tools cannot execute on the API host. Hidden model reasoning is not a product capability. [Runtime](../features/execution/runtime.md).                                                                             |
| Independent encrypted file recovery                            | Chunked file/Git/native-home archives survive provider replacement. Execution success, verified persistence and Git publication are separate outcomes. Recovery verifies actual hashes and continued sessions rather than only checking that a backup exists. [Workspaces](../features/workspaces/README.md).                              |
| Current authority at every boundary                            | Better Auth owns identity; the domain owns memberships/scoped keys/grants. Resource IDs and operation IDs are selectors, not authority. OAuth introspection and delegated calls check current revocation/ownership. Organization switching discards old dashboard cache state. [Identity](../features/identity-integrations/README.md).    |
| Direct MCP plus optional Composio                              | The official MCP protocol and Composio's maintained integrations avoid rebuilding tools while preserving local subject/grant ownership. Credential refresh commits through an independent bounded pool; upstream revocation and consent may require provider action. [Tool security](../features/identity-integrations/tools-security.md). |
| Strict BYOK and prepaid liability                              | All inference crosses the metered native-protocol gateway. BYOK cannot fall back to platform funds. Integer journals, credit lots, reservations and reconciliation retain unknown usage and reversals explicitly. Starter/Pro/Scale entitlements live in one catalog. [Billing](../features/billing/README.md).                            |
| Fair access without promising immediate capacity               | Weighted organization turns, interactive priority and workspace ordering share the existing global capacity lock. Queue deadline, execution timeout and history retention are independent. No preemption, autoscaler or extra queue service. [Scheduling](../features/execution/scheduling.md).                                            |
| Git is versioning, not a destructive event consumer            | GitHub installation authorization and signed webhooks bind the exact repository. Incoming pushes are hints; independent opt-in fetch/merge and publication preserve local conflicts and never force-push.                                                                                                                                  |
| Bounded storage and deletion                                   | Reachability checks, pins, retention and a delayed collector preserve recoverable data. Overage is opt-in and capped. Project purge waits for its undo window and idle execution; accounting identities outlive detailed content.                                                                                                          |
| Public client contracts and explicit transfers                 | CLI/SDKs consume the same API; linking does not upload files. Streaming and rendering are separate, local commands are not inferred from agent text, and file materialization rejects unsafe paths. [CLI](../features/cli/README.md).                                                                                                      |
| Native operating facts, read-only agent management             | SQL reports expose growth, usage and capacity with known missing provider telemetry. Optional PostHog export is metadata-only and outside the request path. No management tool changes infrastructure or reads private prompts/files. [Operations](../features/operations/README.md).                                                      |
| Evidence by boundary                                           | Real PostgreSQL, Git, browser, terminal and native-image fixtures cover their own boundaries. Public metadata probes do not prove authenticated provider behavior. Build and test release artifacts together before cloud promotion. [Testing](../engineering/testing.md).                                                                 |

## Changelog

- Workflow orchestration now hands off after 128 phase advances through the existing PostgreSQL outbox. Queue backoff alone could not fit maximum persistence workloads within provider history limits. Separate orchestration ownership preserves the same native execution and reservation; [the history reference](../features/execution/workflow-history.md) records the budget and recovery tradeoff.
- The launch topology moved from a proposed Railway/E2B/BullMQ stack to Vercel-first hosting, with a standalone SQL poller as the tested control-plane alternative. Provider replacement remains explicit engineering work.
- Implementation replaced proposed restic maintenance VMs, a second Workflow history database, and a universal model proxy with application-owned chunked recovery, existing SQL phase state and a native-protocol metering gateway. These boundaries support exact recovery, revocation and spend accounting.
- Concurrency tests demonstrated a foreign-key lock-upgrade deadlock between checkpoint publication and settlement. Financial projection locks use `FOR NO KEY UPDATE` to coexist with foreign-key `KEY SHARE` locks. The same tests showed batch-wide worker waiting wasting capacity; bounded independent dispatch fixes that measured issue.
- Editor refresh originally overwrote dirty drafts; preserving both draft and original revision makes stale-write rejection reliable. Background live refresh keeps this invariant.
- Dashboard freshness uses indexed current resource stamps and batched pooled reads. This avoids persistent database listeners, shared counter-row contention and an organization event log while making missed-signal reconciliation explicit.
