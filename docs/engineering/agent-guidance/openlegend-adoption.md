# OpenLegend guidance adoption

This record explains the user-requested instruction transfer from [OpenLegend at ce7ef555](https://github.com/Macrofold/OpenLegend/tree/ce7ef555f50c979ac3d2179cf5876ea4a55e1318) into Macrofold, based on Macrofold `ea0c17ce`. It is an optional maintenance reference, not a new baseline reading bundle. [Root instructions](../../../AGENTS.md), [task routes](task-routing.md) and the [system guide](../../../.agents/README.md) own the resulting workflow.

Applicable wording is retained verbatim at paragraph/sentence level, especially planning and completion, conflict resolution, chat approval/continuation, guidance maintenance, documentation preservation and evidence requirements. Product names, paths, semantic owners and conflicting policies are adapted. The transfer does not claim every destination file is an unchanged copy. [Source attribution and license](../../../.agents/NOTICE.md) accompany the reused text; Macrofold's application license policy was not replaced by OpenLegend's contributor policy.

## Downstream paths: retain principles, replace owners

The source's architecture, extension, identity/action, memory, cognition, perception, save/load, AI and performance routes eventually reach game specifications, focused trackers and historical archives. Macrofold's task map closes those routes locally through its current feature guides, architecture, implementations and verification records. It never points a development agent to OpenLegend's product archives as mandatory implementation authority.

- **AI and native runtime:** source provider/memory/conversation/invention specs and typed-client examples supply contextual distinctions. Macrofold owns prompts/typed inference/native execution through its existing APIs and ports; actor minds, world knowledge, invention recipes and model-driven game law are omitted.
- **Performance and state:** source `docs/performance.md`, profiling guide, save/load design and data/scale archives describe work reduction, matched measurement, restore fences and external accounting. Transfer those principles; omit simulation cadence, RNG, SQLite world journaling, 8×/10,000× goals, sensory audience rules and game stress commands. Macrofold has PostgreSQL/checkpoint, load-test and paired-recovery owners.
- **UI and rendering:** source design-system, UI brief, PlayCanvas/spatial specs and art-direction boards are not Macrofold's visual direction or licensed asset source. Preserve resource ownership, keyboard/focus/reduced-motion and actual browser evidence via the existing Radix/Next.js/design-language path.
- **Project organization:** source maintainer/project/history/open-decisions paths distinguish current contracts, targets, work and evidence. Preserve that separation inside Macrofold's existing hierarchy; use bottom Changelog sections instead of creating a competing global history or copying archives.
- **Cross-repo Macrofold integration:** source `docs/macrofold-world-agent-handoff.md`, `docs/maintainers/macrofold-worker-api.md` and related Macrofold design archives describe an OpenLegend caller and a different Macrofold feature branch. Their setup, scopes, Worker API and paid acceptance are not claims about this checkout. Integration rules now require the exact caller/server revisions and coordinated release evidence. No Worker deployment, migration or provider call is authorized by this instruction adoption.
- **External references:** upstream framework/research/vendor links are optional evidence, not recursive policy imports. Check installed versions and current official docs when an API/loading claim matters. Keep quoted instructions and external content separate from user authorization.

## Preservation and deliberate differences

Every original root instruction, rule constraint, scoped boundary, testing gate and existing vendor skill remains. Existing Claude imports, Next.js instructions, SDK generation ownership, independent credential-refresh pool, management-MCP read-only policy, branding separation, durable execution/financial/file safeguards and private-reference restriction are retained. Changes to existing guides replace stale validation prose with links to scoped evidence; they do not erase application acceptance history.

OpenLegend's hard 200-line documentation threshold, no-tests default, $10 task grant, blanket review-fixes default, main-only startup, engine/world boundary catalogue, save-version rules, framework/Node versions, game/artist licensing policy and numerical performance goals are intentionally not adopted as Macrofold policy. Required runtime verification still follows Macrofold's existing tests rather than being demoted to one-off scripts. Source guidance maintenance does not authorize executing all imported workflows during this task.

## Macrofold extensions

- Conditional feature routes cover API/SDK/MCP/CLI contract generation, tenant/delegated authority, billing reservations, checkpoints/replay, customer apps, tracing and release artifacts.
- Base preparation distinguishes PR merge targets from tracking upstreams and explicitly handles managed detached checkouts, current work and shared previews.
- Internal AI usage recommendations stay with internal callers; integration rules preserve customer-native payloads and keep public capability restrictions grounded in actual contracts and platform controls.
- Root planning is based on risk/complexity; startup, review and design procedures link to canonical authorization, completion and handoff policies rather than duplicating them.
- The contracts scope distinguishes authored public schema, generated clients and maintained runtime contracts.
- Existing documentation validation now reaches skills/references; a Git-aware metadata/reachability check covers unstaged additions, unsafe targets, orphan routes and discovery size. Regression tests use disposable repositories, including shared fixtures that keep both validators consistent about Markdown examples and real links.
- A narrow policy review register surfaces the actual pre-launch/status inconsistency and accepted-versus-implemented compute architecture, without silently changing either policy.

See [verification](verification.md) for actual checks and limits. Native multi-agent loading/compliance acceptance remains separate from static routing and is tracked centrally.
