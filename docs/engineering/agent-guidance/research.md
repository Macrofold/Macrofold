# Sources for coding-agent guidance

The [agent rules](../../../.agents/rules/README.md) adapt primary documentation and actual repository instructions to this application's stack. The selection favors clear ownership, small coherent changes, verified contracts, and useful feedback. A company's funding, growth, or repository popularity is not evidence that every convention fits another application.

Upstream pages and default branches change. These links identify the inspected sources; consult the installed dependency documentation before applying version-sensitive advice. This reference is optional context for maintaining the rules, not a prompt to fetch every source for routine code changes.

## Ponytail assessment

[Ponytail](https://github.com/DietrichGebert/ponytail/tree/main) provides a [coding skill](https://github.com/DietrichGebert/ponytail/blob/main/skills/ponytail/SKILL.md), [review skill](https://github.com/DietrichGebert/ponytail/blob/main/skills/ponytail-review/SKILL.md), [repository rules](https://github.com/DietrichGebert/ponytail/blob/main/.agents/rules/ponytail.md), and [benchmark notes](https://github.com/DietrichGebert/ponytail/blob/main/benchmarks/README.md).

Adopt its reuse-first search, flow inspection, root-cause repair, removal of obsolete machinery, and resistance to hypothetical abstractions. Its own guidance preserves requested functionality and security/accessibility checks; simplification should not erase them.

Do not adopt line-removal scoring, universal objections to single-implementation boundaries, minimal-test prescriptions, or a review limited to code size. Our accounting, authorization, durable work, and file recovery need meaningful failure evidence. Its small benchmark tasks and output-size measurements do not establish this application's production quality. No Ponytail dependency, installed skill, persona, or benchmark service is required.

## Framework and security references

| Area                             | Primary guidance                                                                                                                                                                         | Rule adopted                                                                                                                                                                            |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TypeScript                       | [Narrowing](https://www.typescriptlang.org/docs/handbook/2/narrowing.html)                                                                                                               | Validate untrusted input, narrow from `unknown`, preserve strict checking, and avoid casts that hide a boundary mismatch.                                                               |
| Node.js                          | [Event loop and worker pool](https://nodejs.org/en/learn/asynchronous-work/dont-block-the-event-loop)                                                                                    | Bound asynchronous work and input sizes; avoid blocking the serving process or launching unbounded concurrency.                                                                         |
| React                            | [Effects](https://react.dev/learn/you-might-not-need-an-effect)                                                                                                                          | Derive state when possible, keep event work in handlers, and reserve effects for external synchronization with cleanup.                                                                 |
| Next.js                          | [Data security](https://nextjs.org/docs/app/guides/data-security) and installed `next/dist/docs`                                                                                         | Authorize at server boundaries and send minimal safe client data. Match server/client and cache behavior to the installed version; preserve the existing dashboard architecture.        |
| TanStack Query                   | [Query keys](https://tanstack.com/query/latest/docs/framework/react/guides/query-keys), [invalidation](https://tanstack.com/query/latest/docs/framework/react/guides/query-invalidation) | Include authorized resource identity and filters, invalidate through shared owners, and preserve usable refresh states.                                                                 |
| Radix                            | [Accessibility](https://www.radix-ui.com/primitives/docs/overview/accessibility)                                                                                                         | Reuse established interaction primitives while checking application labels, keyboard/focus behavior, and context. A component library alone does not establish accessibility.           |
| PostgreSQL client                | [node-postgres transactions](https://node-postgres.com/features/transactions)                                                                                                            | Use the same checked-out client for a transaction, release it, and preserve tenant context and concurrency invariants.                                                                  |
| Vercel Workflow                  | [Errors and retries](https://workflow-sdk.dev/docs/foundations/errors-and-retries), [sleep](https://workflow-sdk.dev/docs/api-reference/workflow/sleep)                                  | Retried steps need recoverable side effects. Durable sleep still belongs in our history budget; use pinned SDK tests for exact accounting rather than extrapolating a generic example.  |
| Authentication and authorization | [Better Auth security](https://better-auth.com/docs/reference/security), [OWASP authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)            | Keep framework protections, authorize resources server-side, deny invalid authority, and revalidate long-lived/delegated access.                                                        |
| MCP                              | [Security best practices](https://modelcontextprotocol.io/docs/draft/tutorials/security/security_best_practices)                                                                         | Keep credential audiences, consent, proxy boundaries, and untrusted destinations explicit. The linked guidance is a draft; implement against the repository's pinned protocol contract. |

Existing [testing policy](../../../TESTING.md) and [CI documentation](../testing.md) already own Vitest, Playwright, coverage, mutation, and live-test rules. They are reused rather than copied into this source catalog. Tailwind, charting, editors, SDK adapters, and Python clients follow their existing owners and focused task-time documentation; this review does not invent a separate best-practice framework for every dependency.

## Review and tradeoffs

[Google's review guidance](https://google.github.io/eng-practices/review/reviewer/looking-for.html), [small changes](https://google.github.io/eng-practices/review/developer/small-cls.html), and [review comments](https://google.github.io/eng-practices/review/reviewer/comments.html) support examining design, functionality, complexity, tests, and concrete impact. The local policy separates defects from preferences and allows a review with no findings.

The resulting approach chooses one policy owner over indiscriminate deduplication, measured growth over speculative infrastructure, and the smallest complete repair over the fewest lines. Research informs these choices; repository behavior, pinned contracts, and validation determine whether a change is correct.
