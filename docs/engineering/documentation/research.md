Framework identification is limited to observable assets or source configuration. A site's appearance is not proof of its implementation. Where a company is not fully open source, the repository reviewed is its SDK or related public project, not a claim that its hosted platform source is public.

## Decisions for this repository

Keep the existing Next.js application and maintained Markdown renderer. Adopt the navigation, page outlines, keyboard search, clear typography, and Markdown access common to Mintlify/Starlight-style documentation. A second framework or hosted platform would add deployment and content synchronization work without improving the current guide set enough to justify it.

Publish from an explicit manifest. Keep tutorial commands small, show the expected result, and explain errors where users encounter them. Keep technical implementation in linked references and release tasks in a maintainer TODO. Preserve real limits and clearly identify simulation.

## SEO and agent retrieval

Follow [Google's AI search guidance](https://developers.google.com/search/docs/appearance/ai-features): accessible text, descriptive titles, useful internal links, canonical URLs, and truthful content. Google does not require a special AI optimization format for its AI search features.

Provide a [sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview), Markdown alternatives, and an [llms.txt-style index](https://llmstxt.org/) as practical discovery surfaces. These do not promise ranking, citation by an answer engine, or universal agent support. Keep application credentials and tenant data behind their existing authorization boundary, regardless of crawler directives.
