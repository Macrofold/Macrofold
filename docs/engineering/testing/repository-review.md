# Repository review and acceptance

This record covers the repository-wide review and its local acceptance. [Testing and CI](../testing.md) owns current coverage and gates; [release TODO](../../maintainers/TODO.md) owns deferred improvements and cloud acceptance.

## Scope and method

The review inventories repository source, tests, scripts, migrations, configuration, and documentation. Generated declarations, SDK routes, documentation output, catalogs, and the lockfile are checked through their owners and validation. Dependencies, bundled third-party skills, build outputs, credentials, and private runtime/customer data are outside the authored-code review.

The latest work used three bounded rounds:

| Round | Scope                                                                                                                                                                    | Result                                                                                                                 |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| 1     | Repository inventory and risk scan; source tracing across identity, authorization, accounting, scheduling, storage, runtime restore, CLI, and documentation entry points | Fixed device-login cancellation/expiry propagation; corrected stale plan terminology and contributor instructions.     |
| 2     | New marketing routes and examples; full application acceptance, accessibility, and desktop/mobile inspection                                                             | Fixed contrast in four concepts and a demonstrated editor save/refetch race; extended the existing browser regression. |
| 3     | Final diff, sibling draft/streaming flows, generated contracts, documentation hierarchy, and complete local acceptance                                                   | Verified the corrected paths and retained explicit deployment/measurement limits.                                      |

These rounds combine broad automated checks with manual tracing of critical and changed paths. They are **not three independent line-by-line readings of every file**. The earlier request for another exhaustive manual pass remains identified in [review follow-ups](../../maintainers/TODO.md#review-follow-ups); tests and inventory alone do not close it. No fourth review round was undertaken.

Changes preserve the existing provider/domain boundaries, PostgreSQL scheduler, Vercel topology, detailed run replay and financial journal. No service, queue, production dependency, migration or infrastructure change was needed. Existing unrelated working-tree changes are preserved.

## Acceptance evidence

The complete domain suite passes **465 tests in 67 files**, including unit, PostgreSQL integration and Git tests. The source-mapped coverage inventory includes **200 application files**, including untouched modules. [Testing and CI](../testing.md) owns current percentages, module floors and measurement limits. Python is separate: **21 tests** and a **92.13%** combined coverage.py score.

The current runtime image passes all three harnesses' execution, checkpoint restore and conversation continuation, plus OpenCode input and stdio MCP isolation/duplicate-dispatch prevention, with external networking disabled. Fresh installation and a separate database/object/key restore pass, as do portable CLI/TypeScript SDK tarball installation. Native image source maps match the runtime source; this round reused the existing local ARM64 image rather than claiming a fresh image build.

Strict TypeScript, document/link checks, generated contracts, formatting of changed application code and the dependency vulnerability audit pass. The resolved dependency audit reports no known vulnerabilities. Fast mutation testing kills **70/75 mutants (93.33%)**, with five explanatory-string survivors and no timeouts or uncovered mutants. Extended mutation testing scores **90.74%**: 293 assertion kills, one timeout and 30 survivors across 324 mutants. [Mutation interpretation](mutation.md) distinguishes assertion failures, equivalent behavior and remaining gaps.

Fresh application acceptance passes **47 browser journeys**, four CLI subprocess cases, a real terminal journey and Python HTTP/SSE continuation. The marketing checks cover all ten desktop/mobile layouts, keyboard tabs, copy, routing, reduced motion, no-JavaScript rendering and WCAG A/AA scans. All desktop designs and representative mobile screenshots were inspected. Earlier failures exposed four contrast issues and the editor's stale-cache race; failed runs are not represented as successful acceptance. A targeted development-server attempt also lacked the fixture login; final authenticated acceptance used the isolated runner.

All **11 load/dispatch cases** pass with the existing timeout gates, including eight-slot mixed traffic, a 50-slot cohort, newly arriving accounts, cancellation, expiry and worker recovery. No new throughput claim is inferred from these passes. [Scheduling measurements](../../features/execution/scheduling.md#verification-and-measured-limits) retain the separately recorded workload and timing evidence.

## Measurement and deployment limits

Final acceptance uses disposable PostgreSQL databases/filesystems, independent server builds/ports and simulated providers. Its runner does not attach to or stop the running preview. No paid provider call was made. Ordinary acceptance explicitly disables live catalog discovery as well as paid execution.

Coverage uses canonical source maps and a conservative union of observations. Native vendor internals, compiler-unmappable branches, abrupt process termination and unexercised code remain subject to the [measurement limits](coverage.md). Runtime-container acceptance here is local Linux ARM64; hosted Linux AMD64 CI and Vercel/Neon/R2 behavior require the [pre-deployment checklist](../../operations/pre-deployment.md).

Deferred work includes large individual-file diff memory and browser Back/Forward draft recovery. These remain in [review follow-ups](../../maintainers/TODO.md#review-follow-ups). The product is pre-launch with no real users or production runs, so legacy-run pricing migration is not an outstanding task; see the [temporary agent notes](../../../AGENTS.md#temporary-notes-pre-launch).
