# Marketing design research

The current directions consider **all twelve distinct sites** in the design, product-explanation, and API-design lists. Repeated references are counted once. The study uses rendered desktop homepages, hero and lower-page screenshots, headings, code/usage sections, media elements, selected public bundles, and official documentation. It does not copy artwork, imply partnerships, or validate vendor performance claims.

For the selected production direction, prefer a compressed video with a poster when the scene only needs material or camera motion. Use SVG/CSS for explanatory connectors and simple interference. [Motion](https://motion.dev/docs/react) can coordinate component transitions, [Rive](https://rive.app/docs/runtimes/web/web) supports designed stateful graphics, and [Three.js instancing](https://threejs.org/docs/#api/en/objects/InstancedMesh) is a candidate for meaningful particle interaction. These are possible implementation choices, **not new installed dependencies**. The current concept pages need none of them.

## Production animation contract

Keep the poster and all copy available without animation. Load a chosen scene near the viewport, pause when hidden, respect reduced motion and the page pause control, and cap resolution/particle count for mobile. Avoid scroll hijacking, fake telemetry, moving text, flashing highlights, or unbounded animation loops. Test bytes, layout shift, frame time, battery cost, and accessibility on actual devices before promoting a live scene.

The current browser study samples hero and explanatory states; it is not an exhaustive inventory of every responsive breakpoint, hover state, animation frame, or subpage on the reference websites. No accounts, messages, provider calls, or purchases were required.
