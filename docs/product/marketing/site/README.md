## Implementation and motion

The [server page](../../../../apps/web/components/landing/site.tsx) owns content and links; [controls](../../../../apps/web/components/landing/controls.tsx) own tabs, copying, motion preferences, and one delegated pointer listener. Registered CSS properties interpolate normalized pointer coordinates, reflection angle, and a separate slow ambient field on opted-in large headings and primary buttons. Wide linear gradients avoid radial rings and preserve the fixed click area. Pointer updates are coalesced to animation frames; CSS owns ambient movement, without a JavaScript rendering loop. The [story](../../../../apps/web/components/landing/story.tsx) observes native scrolling, schedules at most one animation-frame update, and only changes React chapter state at chapter boundaries. The existing scroll update derives bounded opacity and translation from each untransformed chapter’s viewport position, avoiding feedback into layout or chapter selection. Phone copy fades and moves within reserved reading space. The [diagram](../../../../apps/web/components/landing/diagram.tsx) retains prompt and worker identities; its [dedicated stylesheet](../../../../apps/web/components/landing/diagram.css) owns the finite reveal sequences and responsive scene. The [site stylesheet](../../../../apps/web/components/landing/site.css) owns page layout, copy fades, and material reflections.

Scroll selects a chapter near the midpoint between adjacent text sections; it does not drive a per-pixel animation timeline. CSS runs the short sequence independently: roughly four seconds for the first prompt and files, three to four seconds for additional workers, and three seconds for checkpoint convergence. Leaving a chapter cancels its obsolete entrance effects, so fast scrolling cannot queue stale callbacks. Prompts reserve their full wrapping before letters reveal; filenames use stepped clipping. There is no React update per character. [Container-relative sizing](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries) fits the scene and circular tool layout to the available space.

Existing Next.js, React, Radix tabs, Lucide, and clipboard support are reused. There is no new animation service, renderer dependency, provider request, or telemetry stream. The hero uses pre-rendered video when configured and a clear dark background otherwise; it does not run the particle simulation.

The product diagram starts enabled and changes through the visible Play/Pause control, including when the operating system requests reduced motion. The muted hero video starts automatically, including with reduced motion or data saving enabled; data saving selects the smaller video. Its playback follows the shared control, with no separate hero Play prompt. This is the selected marketing interaction; it does not change dashboard motion preferences. Copy and hover feedback retain gentle color/opacity transitions even when playback is paused with reduced motion enabled. Explicit Pause shows a complete static chapter, so changing chapters or examples never leaves partial text or an empty worker. Scroll-driven chapter movement and fades remain independent of playback. Leaving the story removes its entrance animations; returning replays the visible chapter without requiring Play. Hidden tabs and offscreen decorative regions suspend effects through [CSS animation playback state](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/animation-play-state), then resume automatically without changing the visitor’s choice. Short screens retain their readable static chapter layout. Touch-only devices use ambient light without cursor tracking. Effects release observers, listeners, and pending animation frames on unmount. Without JavaScript, the main copy, first code example, links, and complete use-case explanations remain readable.

The marketing route alias is noindexed and canonicalizes to `/`. Design libraries remain excluded from the sitemap. The homepage does not change authentication, dashboard navigation, or execution behavior.
