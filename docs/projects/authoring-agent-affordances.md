OpenLegend's question qualification found that pinned OpenCode can retry a failed native model request internally, outside the caller's turn identity. Its no-automatic-paid-retry policy therefore needs an explicit platform option, rather than an undocumented change to all customers. Add optional `limits.stop_on_model_error: boolean` (default false), propagated by the existing frozen Run limits and generated public clients. The option admits one outstanding model request so lost settlement also prevents another dispatch. The existing model gateway cancels that Run atomically with settlement after a provider rejection, transport/stream error, or missing final usage; subsequent requests fail admission before contacting a provider. Detect explicit streamed errors before delivering them to the harness so it cannot race settlement with a retry. Existing in-flight requests remain accounted; cancellation does not undo provider work. No native dependency upgrade, new database, money reset or global retry policy.
