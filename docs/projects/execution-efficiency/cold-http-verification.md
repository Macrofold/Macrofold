The earlier [clean Linux qualification](optimization-verification.md#clean-linux-primary-qualification) measured warm handler overhead, not cold framework startup or an application's entire operation. This investigation keeps those boundaries separate.

Current result: the final build's six first requests after readiness measure **72.95–91.67 ms overhead on c8g.xlarge**, all passing; the same build on c7g.xlarge measures **95.38–153.50 ms**, so that topology does not qualify. ### Profiler ownership correction and processor comparison

Review of the compiled capture files exposed two collectors in each sampled process: an idle collector created by Next instrumentation and the collector owning actual route operations. The compiled instrumentation and application routes contain distinct collector/diagnostics modules but share global database pools. This installed nested pool wrappers; expiry could leave an older inactive wrapper installed. It is an ownership/lifecycle defect, not evidence that ordinary SQL statements execute twice.

The unused instrumentation entrypoint is removed. Self-hosted REST readiness initializes the profiler in the same module graph as request attribution; existing transport/step entrypoints and standalone worker initialization remain idempotent. No global collector registry, driver prototype patch or new flag is introduced. The capture duration now starts at serving-composition initialization.
