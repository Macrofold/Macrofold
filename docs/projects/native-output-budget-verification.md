Current integration is local on `codex/native-runtime-memory-packs`, based on main `0101368a0dad68a124b79a99d2644b6110cb70c3`. The original 109-path uncommitted implementation on `codex/native-output-budget-design`, based on `50f59404920b4d6ecce9df89590c9c045d9c5032`, was preserved and three-way reconciled with the newer scheduling/ownership fixes. The original checkout remains unchanged. Historical evidence below retains its original artifact scope; [integrated qualification](#integrated-branch-qualification) records the current V2 image. The [feature specification](native-output-budget-feature-spec.md), [technical design](native-output-budget-tech-design.md) and [native execution guide](../features/execution/runtime.md#native-output-and-completion) define behavior. Local checks do not establish deployment or model quality.

## Delivered behavior

- One admission resolver freezes published capabilities and a per-model-call output allowance. Automatic allowance is 32,768, or 65,536 for high/xhigh/max reasoning and omitted effort on exact Muse Contributor, bounded by published output capacity. An explicit valid override may be larger. Session defaults, per-Run overrides and preset omission retain their defined ownership.
- All six adapters and the gateway consume those accepted values. The independent 8,192 ceilings and OpenCode's hidden 32,000 default no longer compete with admission. Actual outgoing qualification requests carried 65,536 for every harness. Direct inference, spending caps and deadlines retain their prior defaults.
- Explicit length/max-output finishes fail the native Run with `model_output_limit_exceeded`, retain actual usage, deny later model/connector admissions and preserve independently verified checkpoints. Output handling adds no automatic paid repair, separate execution pipeline, database table or migration.
- A bounded provider-answer buffer repairs an actual Hermes failure mode: the SDK replaced `I heard` with its subsequent HTTP 409 error. Only first-failure publication persists the provider answer. `output_text_truncated` identifies a prefix shortened by the separate 4 MiB byte bound. Final UI output respects an authoritative empty result rather than resurrecting older deltas.
- All generated SDKs, native CLI options, customer MCP schemas/instructions, advanced dashboard configuration and documentation use the same contract. CLI output/timeout overrides preserve the Session's saved spending cap unless explicitly changed. The dashboard now inherits saved Session/preset budgets and timeouts before applying an output-only override, and blocks submission until that existing configuration query resolves.

### Fault and concurrency boundary

An explicit output-limit response does not release its terminal success tail when the failure-fence write fails. Disposable fault checks injected lost fence acknowledgments and settlement failures, then reconciled twice without duplicate usage or losing the first failure/answer. The in-flight financial liability remains for reconciliation. Existing strict mode (`stop_on_model_error: true`) also blocks another model admission while that ambiguous request is unsettled. First-writer failure identity/code/text survives later SDK errors; known usage settles once through existing accounting.

With strict mode false, the existing API permits concurrent model admissions. If the durable failure write is unavailable while other admission transactions can still succeed, it cannot establish a cross-process fence; already dispatched work also cannot be recalled. An actual second synthetic request was admitted during a non-strict fence-write outage; the same attempt was blocked by strict mode. This limitation was qualified rather than hidden behind a process-local cache or a global serialization change. Strict mode is required when callers need the existing ambiguous-call spending safeguard. The implementation does not claim atomic rollback of already executed native/local tools or external effects.

## Completion and effect-admission review

The complete affected source/caller diff was reviewed: capability discovery/policy, native admission and frozen model limits, all warm compatibility identities, the gateway and shared stream/capture helpers, six adapters, supervisor/Host cleanup, final publication, CLI/MCP/dashboard and generated REST/SDK surfaces. Generated artifacts were checked against their owning schema; dependencies and private runtime databases were not treated as authored source. The TypeScript SDK/app check was rerun.

### Fixed findings

1. **Truncated responses could execute complete tool arguments.** Actual Codex and Claude Code binaries wrote `hello.txt` when syntactically valid tool arguments preceded an explicit length finish, even though Macrofold correctly failed the Run. Earlier malformed-argument checks did not prove this boundary. The existing shared protocol gate now holds effect-enabling Responses items, Anthropic tool-use blocks and Chat tool-call deltas, plus the terminal tail. The gateway drains usage and commits the existing fence/accounting, then rejects incomplete JSON with a private HTTP 502 or errors SSE without releasing those frames. Successful wire bytes remain unchanged, ordinary text/reasoning stays incremental, and no query, controller or paid retry was added. The public asynchronous Run/result API keeps its existing failure contract.
2. **Warm oversized output could crash the supervisor.** The byte-limit callback used `stopAt` before its declaration when a resumed child emitted during the awaited SIGCONT operation. Move that declaration before callbacks are installed. A disposable Linux fixture widened that existing asynchronous window by 250 ms in both variants: the prior declaration order crashed with `ReferenceError`; the fixed source returned `native_result_too_large`, captured persistence and retained the known conversation ID. This is a deterministic supervisor check with a synthetic worker, not a real-model claim.
3. **The HTTP journey fixture crashed on an intentionally rejected stream.** Reuse the error-handler pattern already present in sibling fixture servers and destroy the affected HTTP response. Expected stream failure no longer becomes an unhandled process error. No new maintained test cases were added.

The behavioral cost is deliberately waiting for the model response and settlement before native tool execution; it prevents an explicit incomplete completion from enabling an effect.

Macrofold execution success means completed native execution and its separately reported persistence; it does not validate game/world rules or authorize an application action. OpenLegend owns schema/domain validation and human approval in its authoritative tools. The platform classifies formal provider completion fields, never narrative meaning. Effects from earlier valid completed calls are not rolled back by a later failed response. These boundaries are recorded in the feature specification and unified harness/runtime guides.
